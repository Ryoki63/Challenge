## 1. 結論（先に 7 行）

1. **iOS v1.0（10/24 機能凍結・10/27 審査提出・10/30〜31 公開）と v1.1（10/26〜11/6 実装・11/9 提出・11/12〜13 公開）を最優先**にする。Android のコードは **11/13 まで `main` に入れず**、実装開始は **11/14** から。
2. Google Play の**個人アカウント（2023-11-13 以降に作成）は、12 人以上が 14 日間連続でオプトインしたクローズドテストが必須**。「テスターは募集せず」は個人アカウントでは成立しない。
3. **条件付き推奨 B: 組織アカウント（D-U-N-S）**。12 人×14 日の公式要件は 2023-11-13 以降の個人アカウントを対象とし、組織アカウントへの同要件の記載は確認できない。Google Play Console の日本向け本人確認書類一覧は、個人事業主が開業届を提出して組織として確認を受けられると明記する [G12]。したがって個人事業主でも B を選べる。実際の開業届・屋号・D-U-N-S の有無、Payments/D&B との名義・住所の一致はオーナー確認が必要（null）。
4. **B の律速は D-U-N-S と D&B のデータ反映**。日本の TSR の新規発番は **30 営業日なら無料**（10/23 申請で **12/8 頃**）、**7 営業日は 15,000 円（税別）**。D&B から Google が見るデータへの反映は**数日〜2 か月**（TSR の説明）。B の公開は、有料 7 営業日を使って早ければ **2026-12-23 頃**、無料の標準で **2027-01-07 頃**、反映が最長なら **2027-03 頃**。
5. **A: 個人アカウント + テスター募集**は規則上可能で、公開は **2027-01-06** を目標にできる。ただしオーナーの「募集せず」の例外が必要。現在の early-pairs は**確定 0 組**、X は **0 posts / 0 followers**（2026-10-20 21:33）なので、知人への個別依頼が主経路になる。
6. **予算の矛盾がある**: 既知の固定費 16,550 円（Apple 12,800 + Supabase Pro 1 か月 3,750）+ 広告上限 10,000 円 + Play 3,750 円 = **30,300 円**で、総損失上限 30,000 円を 300 円超える。有料 D-U-N-S 15,000 円を足すと 45,300 円。LLM 費用を上限内で数える会計なら、さらに大きく超える。DECISION-AND-002 で会計基準を決めるまで支払わない。

## 4. テスター 12 人の確保策の比較

### 4.3 個人事業主の D-U-N-S と Play 組織アカウントの可否

**結論: 日本では個人事業主も組織として本人確認できる。** Google Play Console の日本向け本人確認書類一覧は「個人事業主は開業届（Opening/Closing Notification of a Private Business）を提出して組織として確認できる」と明記している [G12]。また Google は、商用・専門的な活動を行う事業なら組織アカウントを選ぶよう案内する [G2]。よって個人事業主の組織アカウントは **可（開業届による本人確認が条件）**。

これは個別アカウントの審査通過保証ではない。開業届の提出者が代表者として確認できること、Google Payments の組織名・住所が D&B の記録と一致すること、D-U-N-S と本人確認書類が受理されることが必要 [G3][G4][G12]。オーナーの開業届・屋号・D-U-N-S の現状は未確認（null）のため #124 とオーナーが実書類で確認する。事前照会を B の必須ゲートにはしない。

| 必要なもの | 内容 | 備考 |
|---|---|---|
| 屋号 | 組織名として使う名前 | 開業届に屋号を入れる |
| 事業用の住所 | 自宅以外を推奨 | Play 上に公開される。バーチャルオフィス可 |
| 事業用の電話 | SMS または音声通話を受けられる番号 | Play 上に公開される |
| 独自ドメインのメール | 組織のウェブサイトのドメイン | 無料メールでは不可とされる事例あり |
| 組織の証明書類 | 開業届の帳票 + 電子申請等証明データシート | 開業届だけでは不足した、という事例あり |
| D-U-N-S | TSR 経由で無料 30 営業日、または 15,000 円で 7 営業日 | 個人事業主は屋号確認書類。Google の日本向け案内では開業届で組織の本人確認が可能 |

- **D-U-N-S 自体**は実際に事業を行う個人事業主でも申請できる（TSR 指定の屋号確認書類が必要）。Google Play Console の日本向け公式書類一覧でも、開業届を提出する個人事業主は組織として本人確認できる [G12]。個別アカウントの審査通過は保証されない。
- **個人情報の公開**: 組織アカウントでも、法的名称・住所・開発者電話は Play 上に公開される [G3]。自宅住所を避けるなら、事業用の住所・電話を用意する必要がある。
- **B を選ぶ場合の条件**: 開業届・屋号・D-U-N-S の有無と、Google Payments/D&B の名称・住所一致を #124 のチェックリストで確認する。実書類の不足や名義不一致があれば、D-U-N-S 申請前に A（個人 + テスター）または C を再判断する。D-U-N-S が 12/8 頃に取れない場合・Google の本人確認が 2027-01-21 までに終わらない場合は、公開時期を再設定する。

### 4.4 テスター互助コミュニティの規約リスク

- Google は、不正な手段での install count 水増し、他アプリのインストールを主機能として誘引すること、報酬付き評価/レビューを禁止している [G8]。
- 確認した公式条文に「テスター同士の交換参加」全般を禁止する文言はない。したがって互助一般を規約違反と断定しない。一方、本番アクセス申請では tester engagement・実際の利用・収集したフィードバックの説明が必要なため、インストールしたままにするだけの交換ではテスト品質上のリスクがある [G1]。
- **PMO の扱い**: 主経路にしない。利用する場合は対象利用者に近く、任意で実際にアプリを使い、率直なフィードバックを返せる人に限る。金銭・商品・割引で install や review を誘引しない。個別コミュニティの規約は未特定のため未確認。
