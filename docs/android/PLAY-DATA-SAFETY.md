# Google Play 申告回答表 — データセーフティ・コンテンツレーティング・対象年齢・広告 ID

- 対象: Lien Android v1.0（APP-001）/ Issue #124 / 作成: 2026-10-21 JST / 担当: ops-lead
- 目的: Play Console の「アプリのコンテンツ」を**そのまま入力できる下書き**にする。Google の判定・審査を保証するものではない。
- **正本は実装とプライバシーポリシー。** この表と実装が違えば、実装に合わせて表を直す（表に合わせて実装を偽らない）。
- 関連: 登録は [PLAY-CONSOLE-SETUP.md](PLAY-CONSOLE-SETUP.md)、署名・CI は [PLAY-SIGNING-AND-SECRETS.md](PLAY-SIGNING-AND-SECRETS.md)。
- 前提: Android v1.0 は **iOS v1.0 と同じ範囲**（分析 SDK なし・広告なし・課金なし）。課金（Google Play Billing / RevenueCat）と写真アルバムは v1.1 以降。**この前提が #120 で変わったら、この表を更新する。**

## 1. データセーフティ（Data safety）

### 1.1 最初の質問

| 質問 | 回答 | 根拠・注意 |
|---|---|---|
| アプリはユーザーデータを収集または共有するか | **収集する（Yes）** | ニックネーム、匿名ユーザー ID、約束・チェックイン、写真、FCM トークン |
| すべてのユーザーデータは転送時に暗号化されるか | **はい** | Supabase / Edge Functions / FCM は HTTPS（TLS）。平文 HTTP を使わない |
| ユーザーはデータの削除を要求できるか | **はい** | 設定 → アカウント → アカウントを削除。プライバシーポリシーの問い合わせ窓口も使える |
| 独立したセキュリティレビューを受けているか | **いいえ** | 受けていない。「受けている」と偽らない |
| 子ども向けか | **いいえ** | 対象年齢は 13+（§3）。Families ポリシーの対象にしない |

### 1.2 データ種別（Console の選択順）

「収集」= 端末外（サーバー / SDK）へ送信され、保存されるもの。「共有」= 第三者への提供。**Supabase と Google（FCM）は開発者の指示で処理するサービスプロバイダーなので「共有」にしない**（Google の定義）。ペアの相手への表示はユーザー間の共有であり、Google の定義上の「第三者提供」ではない。ただし、実装や契約が変わったら再評価する。

- **エフェメラル（一時的）**: いいえ。ニックネーム・約束・チェックイン・写真・FCM トークンは Supabase に保存する。メモリ内だけで処理して捨てるデータではない。

| Console の分類 | 収集 | 共有 | 必須 / 任意 | 用途 | 追跡 | 暗号化 | 削除 | 根拠・注意 |
|---|---|---|---|---|---|---|---|---|
| Personal info → **Name** | する | しない | **必須** | App functionality | しない | する | できる | ニックネーム（8文字以内）。本名不要。ペアの相手にだけ表示 |
| Personal info → **User IDs** | する | しない | **必須** | App functionality | しない | する | できる | Supabase の匿名ユーザー UUID。アカウント識別 |
| Photos and videos → **Photos** | する | しない | **任意** | App functionality | しない | する | できる | チェックインに任意で 1 日 1 枚。ペアの相手だけが署名付き URL で見られる。**写真を選ばなくてもアプリを使える** |
| App activity → **Other user-generated content** | する | しない | **必須** | App functionality | しない | する | できる | 約束のタイトル・絵文字・リマインド時刻、チェックイン記録、リアクション、スタンプ |
| Device or other IDs → **Device or other IDs** | する | しない | **必須**（実装次第で任意） | App functionality | しない | する | できる | FCM の登録トークン / Firebase installation ID。通知の送信に使う。**通知を拒否しても SDK が ID を生成する実装なら「必須」**。拒否時に生成しない実装なら「任意」にできる（§6 の確認項目） |
| Financial info → **Purchase history** | **v1.0 では収集しない** | — | — | — | — | — | — | v1.0 は課金なし。v1.1 で Google Play Billing / RevenueCat を入れたら、購入履歴・購読状態を追記する |
| App activity → **App interactions** | **収集しない** | — | — | — | — | — | — | 分析 SDK を入れず、タップ・画面遷移のイベントを送らない（REQUIREMENTS §7 / D6）。チェックイン記録は「Other user-generated content」で申告する |
| App info and performance → **Crash logs / Diagnostics** | **収集しない** | — | — | — | — | — | — | Crashlytics 等のクラッシュ SDK を入れない。Android vitals は Play の機能であり、アプリの Data safety の「収集」とは別 |
| Location（approximate / precise） | **収集しない** | — | — | — | — | — | — | 位置情報の権限を要求しない。IP から推定した位置も使わない |
| Personal info → Email / Address / Phone / Race / Political / Sexual orientation / Other | **収集しない** | — | — | — | — | — | — | メールアドレス・電話番号・住所はアプリでは取得しない（ストアの連絡先は開発者向けであり、アプリの収集ではない） |
| Messages（Emails / SMS / Other in-app messages） | **収集しない** | — | — | — | — | — | — | チャット機能はない。約束・チェックインは「Other user-generated content」 |
| Audio / Files and docs / Calendar / Contacts | **収集しない** | — | — | — | — | — | — | 権限を要求しない |
| Health and fitness | **収集しない** | — | — | — | — | — | — | 健康・フィットネス機能はない |
| Web browsing | **収集しない** | — | — | — | — | — | — | WebView で外部サイトを巡回させない |
| In-app search history | **収集しない** | — | — | — | — | — | — | 検索機能はない |

### 1.3 データの取り扱いの補足（Console の自由記述・ポリシー用）

- **保存場所**: Supabase（Postgres / Storage）。国外のサーバーに保存される可能性がある。プライバシーポリシー §4 に記載済み（事業者名・連絡先のプレースホルダは G4 で埋める）。
- **保存期間**: アカウントが存続する間。アカウント削除でニックネーム・約束・チェックイン・写真を削除する。バックアップからの完全削除に要する期間は **未確定（null）**。Supabase のバックアップ設定を確認して確定値を記入する。**推測で「30日」と書かない。**
- **委託先**: Supabase（DB / Storage）、Google（FCM）。いずれも開発者の指示で処理するサービスプロバイダー。第三者提供ではない。
- **写真の共有範囲**: ペアの相手だけ。署名付き URL（有効期限あり）。ストアのスクリーンショット・シェア画像にはチェックイン写真を含めない。
- **削除要求 URL**: プライバシーポリシーの公開 URL（G4 で確定）。アプリ内の削除導線も併記する。
- **年齢**: 13+ を想定。13 歳未満を対象にしない（§3）。

### 1.4 データセーフティで「嘘になる」典型例（避ける）

- 分析 SDK を入れていないのに「Analytics」と答える（またはその逆）。**実装の依存関係を確認する。**
- Supabase を「第三者共有」と答える（サービスプロバイダーは共有ではない）。ただし、Supabase の利用規約・データ処理契約が変わったら再評価する。
- 写真を「必須」と答える（任意。選ばなくても使える）。
- アカウント削除があるのに「削除できない」と答える（またはその逆）。
- 広告 ID を使っていないのに「使う」と答える（§4）。

## 2. コンテンツレーティング（IARC 質問票）

### 2.1 カテゴリ

- **推奨: Social（ソーシャル / コミュニケーション）**。ペア間で写真・約束・リアクションを共有し、ユーザー同士が交流するため。UGC の質問が確実に出る。
- 「Lifestyle / 習慣」を選ぶと UGC の質問が出ず、実態より低いレーティングになる可能性がある。**実態に合うカテゴリを選ぶ。**
- ゲームではない。ニュース・金融・健康・政府アプリではない。

### 2.2 質問への回答（下書き）

IARC の質問は国・時期で変わる。画面の文言に合わせて、以下の意図で答える。

| 質問の種類 | 回答 | 補足 |
|---|---|---|
| 暴力（現実的・空想的） | **なし** | 戦闘・虐待・流血の表現なし |
| 恐怖・ホラー | **なし** | 怖い演出なし |
| 性的表現・ヌード | **なし** | 性的なコンテンツなし |
| 卑猥な言葉 | **なし**（アプリ側の定型文） | ユーザーがニックネーム・約束に自由入力できるため、**UGC 経由で不適切な言葉が入る可能性はある**。通報・ブロック・削除で対応する |
| 薬物・アルコール・タバコ | **なし** | 表現なし |
| ギャンブル | **なし** | 賭け・抽選・課金ガチャなし |
| ユーザー生成コンテンツ（UGC） | **あり** | ニックネーム、約束、写真、リアクション。ペアの相手だけに表示 |
| ユーザー同士の交流 | **あり** | 招待コードでペアになった相手とだけ。不特定多数への公開・DM・掲示板はない |
| 位置情報の共有 | **なし** | 位置情報を取得しない |
| 個人情報の共有 | **あり（ニックネーム・写真）** | 本名・住所・電話・メールは共有しない。写真は任意 |
| デジタル購入 | **v1.0 ではなし** | 課金を入れたら「あり」に変更 |
| 広告 | **なし** | 広告 SDK なし |
| 外部リンク | **あり（規約・プライバシーポリシー・問い合わせ）** | ブラウザで開く。外部サイトのコンテンツは管理外 |
| その他（ギャンブル以外の課金・抽選） | **なし** | v1.0 はなし |

### 2.3 予想レーティング

- UGC とユーザー間交流があるため、**IARC の判定は 12+ 以上（15+ の可能性もある）**。日本では 12+ / 15+ のいずれかで表示される。
- **「全年齢（3+）」を想定しない。** UGC・写真共有・通報導線の実装が審査で説明できる状態にする。
- 最終的なレーティングは IARC の判定が正。この文書の予想をそのまま申請しない。

### 2.4 レーティング前に必要な実装（Android v1.0）

- **通報**: 不適切な写真・コンテンツを運営に通報できる（iOS の通報導線と同じ）。問い合わせメールでも可。
- **ブロック**: ペア解消で相手の写真・共有コンテンツを見られなくする。
- **削除**: 運営が規約違反のコンテンツを削除できる。利用規約に明記する。
- **年齢**: 13 歳未満を対象にしない。プライバシーポリシーの未成年の扱いと矛盾しないようにする。
- これらが Android v1.0 に無いまま申請すると、UGC の申告と実装が矛盾する。**#120 / #123 の範囲を確認する。**

## 3. 対象年齢（Target audience and content）

| 質問 | 回答 | 理由 |
|---|---|---|
| 対象年齢層 | **13–15、16–17、18+ を選択。0–5 / 6–8 / 9–12 は選択しない** | カップル向けの習慣アプリ。UGC・写真共有があり、子ども向けに設計していない |
| アプリは子ども向けに設計されているか | **いいえ** | Families ポリシーの対象にしない |
| 子どもに魅力的なデザインか | **いいえ** | 植物・静かな UI は子ども向けのキャラクター・ゲーム要素ではない |
| 保護者向けの説明が必要か | **いいえ** | 子ども向けではない |
| 広告を含むか | **いいえ** | 広告 SDK なし |
| アプリ内購入があるか | **v1.0 ではいいえ** | v1.1 で課金を入れたら「はい」に変更 |
| 位置情報を使うか | **いいえ** | 権限なし |
| カメラ・マイクを使うか | **v1.0 ではカメラなし（写真はフォトピッカー）** | v1.0.1 でカメラ撮影を入れる場合は「はい」に変更（#120） |
| 連絡先・SMS・通話履歴を使うか | **いいえ** | 権限なし |
| 新聞・ニュースアプリか | **いいえ** | — |
| 政府・行政のアプリか | **いいえ** | — |
| 金融商品・暗号資産を扱うか | **いいえ** | — |
| 健康・医療を扱うか | **いいえ** | — |
| VPN を使うか | **いいえ** | — |
| アクセシビリティサービスを使うか | **いいえ** | — |
| アカウント作成があるか | **はい（匿名）** | メール・電話の登録なし。UUID を発行 |
| アカウント削除があるか | **はい** | アプリ内の設定から削除 |

- **13+ を選ぶ理由**: 子どもの個人情報を扱わないため。13 歳未満を対象にすると、各国の保護者同意・Families ポリシーの追加要件がかかる。Lien の設計（ペア・写真・課金）は 13+ が現実的。
- 対象年齢を 18+ にすると審査は単純になるが、18–19 歳のユーザーを逃す。**13+ を推奨**。最終判断はオーナー（#120 の要件と合わせる）。

## 4. 広告 ID（Advertising ID）の申告

| 質問 | 回答 | 根拠 |
|---|---|---|
| アプリは広告 ID を使用するか | **いいえ** | 広告 SDK・解析 SDK を入れない。`AdvertisingIdClient` を呼ばない |
| 広告目的で他の端末識別子を使うか | **いいえ** | FCM トークンは通知の配信にだけ使う。広告・プロファイリングに使わない |
| 広告を表示するか | **いいえ** | 広告なし |
| トラッキング（ATT 相当）をするか | **いいえ** | トラッキングなし。iOS の PrivacyInfo も `NSPrivacyTracking=false` |

### 4.1 Manifest の確認（提出前に必ず実行）

```bash
# AD_ID 権限が無いこと（出たら、その依存関係を外すか、広告 ID の申告を見直す）
grep -R "com.google.android.gms.permission.AD_ID" products/lien/android || echo "AD_ID permission: none"

# 広告 SDK が入っていないこと
grep -R "play-services-ads\|com.google.android.gms.ads\|applovin\|unityads\|ironsource" products/lien/android || echo "ads SDK: none"

# 解析 SDK が入っていないこと（v1.0 の D6）
grep -R "firebase-analytics\|com.google.firebase.analytics\|amplitude\|mixpanel\|telemetrydeck" products/lien/android || echo "analytics SDK: none"
```

- 依存関係は `./gradlew :app:dependencies` でも確認する。**推移的依存**で `play-services-ads` が入ることがある。
- `AD_ID` 権限がマージされると、Play Console の広告 ID 申告と矛盾する。見つけたら依存を外すのが先。**申告を実装に合わせて「使う」に変えない。**
- FCM の Firebase installation ID は「Device or other IDs」として Data safety に申告する（§1.2）。広告 ID ではない。
