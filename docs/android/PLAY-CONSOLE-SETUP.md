# Google Play Console 登録手順 — オーナー用1枚 + 補足

- 対象: Lien Android v1.0（APP-001）/ Issue #124 / 作成: 2026-10-21 JST / 担当: ops-lead
- 目的: **オーナーが 30 分で登録入力まで終えられる**ように、人間がやることを1枚にまとめる。Google 側の本人確認・D-U-N-S 取得・審査の待ち時間は 30 分に含まない。
- 範囲外: 公開ボタン、本番リリース、契約・送金・銀行・税務、認証情報の作成代行。**認証情報・本人確認書類の画像・カード番号・住所は、このリポジトリにも Issue にも書かない。**
- 関連: 署名・Secrets は [PLAY-SIGNING-AND-SECRETS.md](PLAY-SIGNING-AND-SECRETS.md)、申告回答は [PLAY-DATA-SAFETY.md](PLAY-DATA-SAFETY.md)、日程・テスター確保は #119、Android 実装は #121。

## B. 個人アカウントと組織アカウントの違い

Google Play の機能（アプリ公開・課金・ユーザー招待）はどちらでも同じ。違うのは**本人確認の書類**と、**公開までのテスト条件**。

| 項目 | 個人アカウント | 組織アカウント |
|---|---|---|
| 向いているケース | 個人開発・趣味・学習。屋号なしで進める場合 | 法人・個人事業主・屋号で出す場合。請求・契約の名義を分けたい場合 |
| 必須の確認 | 政府発行の本人確認書類（氏名・住所が一致すること） | **D-U-N-S 番号**（無料。D&B で取得）、政府発行ID、組織の証明書類 |
| 登録料 | 25 USD（1回） | 25 USD（1回） |
| 公開前のテスト | **2023-11-13 以降に作成した個人アカウントは、12 人以上が 14 日連続でクローズドテストに参加する必要がある** | この 12人×14日 の条件は個人アカウント向け。組織アカウントは対象外（Google の案内を確認） |
| デバイス確認 | あり（Android 10 以上の実機。2024 年初頭以降の新規個人アカウント） | 個人アカウント向けの案内。組織の場合は画面の指示に従う |
| ストアに表示される情報 | 登録した開発者名・連絡先など。個人名・住所が見える可能性がある | 組織名・住所。屋号を出したい場合はこちら |
| 公開までの最短ルート | 12 人を集め、14 日連続で参加してもらい、本番アクセスを申請する | D-U-N-S 取得 → 本人確認 → 内部テスト → 公開申請（12人×14日なし） |
| 注意 | 「テスターを募集せずに公開」は**できない**。12 人未満・14 日未満・途中でオプトアウトした人は数えない | D-U-N-S の取得に日数がかかる可能性がある。取得完了までは登録を進められない |

### どちらを選ぶか（この文書では決めない）

- 2026-10-21 時点の優先順位は **iOS v1.0 の 10/31 公開**。Android の公開日は未確定で、#119 が日程・テスター確保・組織アカウント可否を比較している。
- **個人アカウントを先に作ると、12人×14日の条件が付く**。組織アカウントに切り替えたい場合に同じアカウントのまま種別を変えられるかは保証されない。**#119 の結論が出る前に、個人アカウントで登録を確定しない。**
- 組織アカウントは D-U-N-S が必須。D-U-N-S は無料だが、取得に時間がかかる。**「D-U-N-S が今日取れる」と仮定しない。**
- 判断はオーナー（#119 の比較表と推奨案を見て決める）。この文書は両方の手順を並べるだけで、種別を独断で選ばない。

## C. 登録の詳細（画面の順）

### C1. アカウントと支払い

1. オーナー本人の Google アカウントで <https://play.google.com/console> を開く。共有アカウント・使い回しのアカウントは使わない。
2. 「デベロッパーアカウントを作成」を選び、Developer Distribution Agreement を読んで同意する。
3. 氏名・住所・電話番号を入力する。**本人確認書類と同じ表記**にする（旧姓・屋号・略称を混ぜると確認で止まりやすい）。
4. 25 USD を支払う。使えるのは MasterCard / Visa / American Express / Discover（米国のみ）/ Visa Electron（米国外のみ）。**プリペイドカードは不可**。名義が登録者と一致していることを確認する。
5. 支払い後の領収書は Fin（#126）へ渡す。総損失上限 3 万円の内数として計上する。**領収書の画像・カード番号はリポジトリに置かない。**

### C2. 本人確認

- 個人: 政府発行の身分証明書（運転免許証・パスポート・在留カード等）。氏名・住所が登録内容と一致していること。
- 組織: D-U-N-S 番号、政府発行ID、組織の証明書類（登記簿・定款・請求書等、Google の指定による）。
- 確認は Google 側で行う。**こちらから書類を偽造・加工しない。** 不一致と言われたら、登録情報を直して再提出する。それでも通らない場合は、新しいアカウントを作らず Google Play サポートに問い合わせる。
- 個人アカウントは、Play Console モバイルアプリで Android 10 以上の実機（root 化されていないもの）によるデバイス確認がある。エミュレータでは代替できない。

### C3. アプリの作成

1. Play Console → Home → 「アプリを作成」。
2. アプリ名: **Lien**（あとで変更可）。既定言語: **日本語（ja-JP）**。アプリ / ゲーム: **アプリ**。無料 / 有料: **無料**（v1.0 は無料。課金は v1.1 以降で別途）。
3. 連絡先メール: ユーザーが問い合わせできるアドレス。個人情報をリポジトリに書かないため、値はここでは示さない。
4. 「Developer Program Policies」「US export laws」を確認し、**Play App Signing の利用規約に同意**する。新規アプリは自動的に Play App Signing に登録され、Google がアプリ署名鍵を持つ。
5. パッケージ名（applicationId）を確認する。**初回アップロード後に変更できない。**
   - 推奨: `com.ryoki63.lien`（iOS の `LIEN_BUNDLE_ID_BASE` と同じ文字列。ストアが違うので衝突しない）。
   - 現在の Android 雛形は `com.example.lien`（仮 ID）。**このまま初回アップロードしない。** #121 の雛形を最終 ID に変えてからアップロードする。
   - 既に同じパッケージ名のアプリが Play にある場合は、新規作成せず停止する。

### C4. 内部テスト（登録直後にできる）

1. Play Console → 「テストとリリース」→「テスト」→「内部テスト」。
2. テスターをメールアドレスで最大 100 人まで登録する。まずオーナー + 開発用の Google アカウント 1〜2 個でよい。
3. 「新しいリリースを作成」から AAB をアップロードする。CI を使う場合は [PLAY-SIGNING-AND-SECRETS.md](PLAY-SIGNING-AND-SECRETS.md) の Secrets を設定し、`.github/workflows/lien-play.yml` を手動実行する。
4. 内部テストのリンクをテスターに配る。反映には数時間かかることがある。
5. 内部テストは**本番公開の条件（12人×14日）を満たさない**。個人アカウントの本番アクセスには、別途クローズドテストが必要。

### C5. クローズドテスト（個人アカウントのみ）

- 12 人以上が**14 日連続でオプトインしたまま**である必要がある。途中でオプトアウトした人、14 日未満の人、12 人に満たない場合は本番アクセスを申請できない。
- テスターは「募集せず」にはできない。既存の early-pairs・X フォロワー・知人などから集める。**テスター互助コミュニティは規約違反リスクがあるため、#119 の比較と承認なしに使わない。**
- 14 日は Google のサーバー側で判定される。申請前に、Play Console のクローズドテスト画面で「12 人以上が 14 日連続」と表示されることを確認する。
- 本番アクセス申請では、テスト方法・アプリの目的・本番準備について質問に答える。**申請・公開ボタンは人間が押す。エージェントは代行しない。**

## D. 登録が終わったら（CI の前提）

以下は人間が行う。値はリポジトリに書かない。詳細は [PLAY-SIGNING-AND-SECRETS.md](PLAY-SIGNING-AND-SECRETS.md)。

1. アップロード鍵（keystore）を作る。**Play のアプリ署名鍵とは別物**。Google が持つのはアプリ署名鍵、CI が使うのはアップロード鍵。
2. GitHub の Environment `play-internal` に Secrets を登録する（名前だけ: `ANDROID_UPLOAD_KEYSTORE_BASE64` など）。
3. Google Cloud でサービスアカウントを作り、Android Publisher API を有効化し、Play Console で「Release apps to testing tracks」だけを付与する。**Admin も本番公開権限も付けない。**
4. `.github/workflows/lien-play.yml` を `publish=false` で一度実行し、ビルド・テストが緑になることを確認する。次に `publish=true` で内部テストへアップロードする。
5. ストア掲載文・スクリーンショットは #125、データセーフティ・コンテンツレーティングは [PLAY-DATA-SAFETY.md](PLAY-DATA-SAFETY.md)。

## E. 停止条件（ここに当てはまったら止める）

- アカウント種別が #119 で決まっていない。→ 登録を確定しない。
- 25 USD 以外の支払い、銀行口座・税務情報・身分証明の追加提出を求められた。→ 登録の範囲外。オーナー / Fin に確認する。
- 氏名・住所・屋号が本人確認書類と一致しない。→ 一致させてから再開する。虚偽の書類は使わない。
- 同じパッケージ名のアプリが既に存在する。→ 新規作成しない。パッケージ名を再検討する。
- Google から「12 人×14 日」の条件を満たしていないと言われた。→ テスターのオプトイン状況を確認する。条件を満たさずに本番申請しない。
- 認証情報・カード番号・本人確認書類の画像を、Issue・PR・チャット・日報に書きたくなった。→ 書かない。場所だけを共有する。
- 同じ操作を 2 回失敗した。→ 3 回目を試さず、Google Play サポートまたはオーナーに渡す。
