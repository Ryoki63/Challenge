# UI/UX レビューと改訂(2026-10-25)

- 対象: `products/lien`(iOS アプリ本体・ウィジェット・招待/設定/履歴/ペイウォール)
- 依頼: 「UIUX の観点でレビューし改訂する。現時点のものは必ずしもよい仕上がりではないことに留意する。既存に規定されず、常識を壊して、前提を置かずに」
- 評価の枠組み: 参考記事 [UI八原則](https://note.com/d900/n/ne3686d8bfea7)(でいきゅうひゃく)の8原則
- 方法: 実装を読む → シミュレータで実画面を操作して撮影 → 主要画面を `ImageRenderer` で実描画 → 8原則に当てて欠陥を列挙 → 改訂 → 全テストで検証
- 画像: `ios/build/ui-review/`(レビュー用ハーネス `LienTests/UIReviewRenderTests.swift` の出力。コミットしない)

> 前提を置かない、の意味: 「このアプリはこういう画面構成だ」を所与にせず、
> **「2人で1日1タップの記録をする」という仕事だけ**から画面を組み直したらどうなるかを基準にした。
> 既存の構成は、その基準に照らして落ちたものを落とした。

---

## 0. 結論(3行)

1. **ホームは「縦に積んだ機能一覧」になっていて、主役の1タップが最後にあった。** 画面の 84% の位置、しかも日によって動く。ここを最優先で直した(画面下に固定)。
2. **アプリにアクセントカラーが無く、ボタンもトグルもリンクも iOS 既定の青だった。** ブランド(セージグリーン)は Web とシェア画像にしか無く、アプリだけ別プロダクトの色をしていた。ブランド色を1か所に定義して全体に効かせた。
3. **オンボーディングの最初の画面に、アプリの主役(タネの子)が出ていなかった。** SF Symbols の `leaf.circle` と `bell.badge` だけで、差別化要素が最初の3画面に一つも無かった。本物の植物に置き換えた。

## 1. 直したこと(原則別)

### 🐎 移動到達性 / 🧭 秩序予測性 — 主役の位置

| 事実 | 改訂 |
|---|---|
| チェックインボタンは、植物(240pt)・ストリーク(3行)・シェアボタン・チケットバッジ・今日のチップ(98pt)の**後**、画面の 84% の位置にあった(実測: iPhone 17 Pro / 874pt で y=734) | スクロールの外に出し、`safeAreaInset(edge: .bottom)` で**画面下に固定**(`HomeActionBar`)。実測で 92% の位置に常時ある |
| 位置が状態で動いた(シェアボタン・チケットバッジ・つつく・リアクションが出たり消えたりするたびに、ボタンが上下する) | 帯の中身は「補助の行 + 主役のボタン」で固定。状態で増減するのは帯の高さだけで、主役は常に最下段 |
| 小さい端末(667pt)ではスクロールしないと押せなかった | 固定したので端末高さに依存しない |

### 👁️ 視認識別性 / ✨ 洗練明瞭性 — 色と階層

| 事実 | 改訂 |
|---|---|
| `Assets.xcassets` に `AccentColor` が無く、`ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME` も未設定。`.borderedProminent`・`Toggle`・`Link`・選択状態がすべて**システムブルー**だった。ブランド色(#3D6B52)は Web の CSS と `LienColors.shareAccent` にしか無かった | `AccentColor.colorset`(light #3D6B52 / dark #8FC7A8)を追加し、`project.yml` で全体のアクセントに指定 |
| `LienColors.done = Color.green`(彩度の高いシステム緑)。クリームの背景で浮いていた | ブランド緑に統一(ダークは明るい緑) |
| 未完のチップを `.opacity(0.55)` で**チップ全体**を薄くしていた。名前も約束も一緒に薄くなり、`caption` + `.secondary` と重なって読みにくかった | 不透明度をやめ、**背景**(淡い緑 / グレー)と**印の色**で表す。文字は常に不透明 |
| 今日のチップが縦4行(98pt)で、主役のボタン(47pt)より背が高かった | 横1行(絵文字 / 名前と約束 / 印)に畳んだ |
| ストリークが「ふたりの記録 / 🔥 23日 / 最高記録 40日」の3行中央揃えで、植物とボタンの間で視線を割っていた | 1行に畳んだ(`StreakLine`)。数字だけを強く、ほかは小さく添える |
| シェアボタンが全幅 `.bordered` で、ホームの中ほどを占めていた(副次的な操作なのに主役と同じ面積) | 補助の行の小さなボタンに移した |
| つつく・リアクションが、それぞれ全幅ボタン + 専用メッセージ行で、同じ強さの行が2本できていた | 1行の小さなボタン2つ + メッセージ行1本に統合(`SecondaryActionRow`) |
| お休みチケットのバッジが常時、画面の中ほどにあった | スクロール内容の最下部へ(0枚でも出す要件は維持) |

### 👁️ 視認識別性 — オンボーディング

| 事実 | 改訂 |
|---|---|
| 1画面目が `Image(systemName: "leaf.circle")`、3画面目が `bell.badge`。アプリ唯一の差別化要素であるタネの子が、最初の3画面に一度も出なかった | 1画面目を `PlantCharacterView`(本物の絵)に置き換え |
| 3画面あるのに、何画面目かも残り何画面かも分からなかった | 3点のステップ目印を常時表示(`OnboardingStepIndicator`)。VoiceOver は「3ステップ中1」 |
| 1・3画面目が `Spacer` だけの `VStack` で、文字を大きくすると切れた | `ScrollView` + 下部固定のボタン(`safeAreaInset`)に変更 |
| 絵文字パレットの選択が 20% の色だけ。どれが選ばれているか弱かった | 枠線を足し、`.isSelected` を付けた |

### 🧠 判断低減性 — 押せない理由

| 事実 | 改訂 |
|---|---|
| ニックネーム未入力・規約未同意で送信ボタンが無効になるが、**理由がどこにも出ない**(空欄のときはエラー文言も出ない実装だった)。押しても何も起きず、詰まる | 無効のあいだだけ理由を1行出す(「ニックネームを入れると、次へ進めます」「…同意が必要です」) |

### 操作応答性 — 言語の混在

| 事実 | 改訂 |
|---|---|
| 招待の有効期限が `formatted(date:time:)` で、端末ロケール依存。日本語 UI の中に「Oct 28, 2026 at 5:56 まで有効」と英語で出た(実機で確認) | `Date.FormatStyle(locale: ja_JP)` に固定 |

### ♻️ 呼吸循環性 / 👁️ 視認識別性 — 履歴

| 事実 | 改訂 |
|---|---|
| ふたり達成が 5pt の点2つ。片方だけの日(点1つ)と、凡例を見ないと区別できなかった。月を眺めても「続いた期間」が模様として読めない | 達成は**塗りの帯**(16×6pt)に。点は片方だけの日に残した。月が縞として読める |

## 2. 直していないこと(意図的)

- **設定・履歴の入口が両方とも右上**で、親指から最も遠い。設定は歯車、履歴はカレンダーで、同じ角に2つ並ぶ。→ §3 の提案に含めた(今回は導線の位置を変えると `RootView` の構造まで動くため見送り)
- **ウィジェットの `WidgetStatusChip` は `opacity(pendingOpacity)` のまま。** アプリと作法が揃っていないが、ウィジェットは 154pt の極小面で、淡くする利点が勝つと判断した(要再検討)
- **植物の上に常時 37pt の空き**(`WhisperBubbleMetrics.roomAbovePlant`)。吹き出しは数秒しか出ないのに、常に場所を空けている。`HomeRenderChecksTests` が画素で守っている約束なので、今回は触っていない
- **`DeviceTokenDebugView`(G1 計測用)が DEBUG ビルドのホームと招待画面に出る。** Release には入らないが、TestFlight のスクショに写る
- **ペイウォールは文字の壁。** 見出し・説明・特典・プラン・購入・復元・規約が同じ強さで縦に並ぶ

## 3. 提案(常識を壊した組み直し)

現行の「ホーム = 縦に積んだ機能一覧」を捨て、**「今日」という1つの面**にする。

```
┌─────────────────────────────┐
│ ゆうき ・ 23日          ⚙  │  ← 1行。相手と記録だけ。設定は右上
├─────────────────────────────┤
│                             │
│         (タネの子)          │  ← 画面の6割。葉の開閉がそのまま状態
│                             │
│   「ゆうきが待ってるよ」    │  ← 状態は1行だけ
│                             │
├─────────────────────────────┤
│  [📷]  [👉]  [❤️]  [↗]      │  ← 補助はアイコン4つ(文言なし)
│  ┌───────────────────────┐  │
│  │        できた!        │  │  ← 親指の真上。常に同じ場所
│  └───────────────────────┘  │
└─────────────────────────────┘
```

- **今日のチップを廃止**する。チップは「自分」と「相手」の2枚だが、植物の葉がすでに同じことを示している(左=自分・右=相手が開いているか)。同じ情報を2つの表現で持っている。葉を主にし、言葉は「相手が待ってるよ」の1行に寄せる
- **ストリークを数字1つに**する。日数は植物の段階とゲージが語るので、数字は「ふたりの記録」の1行に縮める
- **チケットは使った日と0枚の日だけ出す。** 常時出すと「残り2枚」が常に視界に入り、守られている実感より在庫管理の印象になる
- **履歴はホームの下タブではなく、植物の長押し**にする。月に数回しか見ないものに常設の入口を与えない
- **オンボーディングは3画面をやめて1画面**にする。コンセプト・名前・通知は1枚に収まり、3画面に割る理由が無い(実測でも1画面に収まる)。ステップ目印も不要になる
- **約束設定は「候補から選ぶ」を先に出す。** 自由入力の空欄から始めると、何を書けばいいかの判断が発生する(「筋トレ」「ストレッチ」「読書」…の3択 + 自由入力)

## 4. 検証

- `xcodebuild test`(iPhone 17 Pro / iOS 26.5): **1231 件すべて成功**
- 追加した描画ハーネス `UIReviewRenderTests`(10枚)で、オンボーディング3画面・約束設定・招待・設定・ペイウォール・ホーム3状態を実描画
- シミュレータで実際にオンボーディング → 約束設定 → ホーム → チェックイン → 設定 → 招待発行まで操作し、固定した帯が機能すること、完了状態に切り替わることを確認
- ストア用スクリーンショット(`StoreScreenshotRenderTests`)を新しい帯に追随させ、再生成した

## 5. 残るリスク

- 帯の `.background(.bar)` は半透明の材質。ダークモードと、植物が帯の下を流れたときの可読性は実機で見ていない
- 帯の高さは、つつく・リアクション・シェアが出ると増える(最大で約 40pt)。主役の位置は変わらないが、植物の見える面積は減る
- ステップ目印は 3画面前提。§3 の1画面化をやるなら一緒に消す
