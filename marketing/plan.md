### 5.1 広告を使う場合の上限と停止条件

- 前提(未了なら**使わない**): ASC にアプリレコードがある / Apple Search Ads の支払い方法が登録済み(オーナーの作業) / ストア文言の承認(G4・mkt-review)がある
- 1 件の定義: **1 キャンペーン = キーワード 3〜5 語の手動入札**。専用のクリエイティブは作らず、ストアのメタデータをそのまま使う(文面の承認は G4 と mkt-review で足りる)

| 項目 | 上限 |
|---|---|
| 1 件あたりの日予算 | **1,000 円** |
| 1 件あたりの累計 | **5,000 円**(到達で自動停止) |
| 入札 | **60 円 / タップ**まで |
| 件数 | **最大 2 件** |
| 全体の累計 | **10,000 円** |
| 出稿してよい期間 | 11/4〜11/22 に開始。**11/23 以降は新規出稿しない**(月末の判定に間に合わない) |

- 停止条件(1 つでも当てはまったら**即停止**。再開は mkt-lead の新しい判断と mkt-review の承認が要る):
  1. 累計 3,000 円を使った時点で **CPI(消費額 ÷ そのキャンペーン経由のインストール数)> 300 円**
  2. **招待→ペア成立率が 2 週続けて 40% 未満**(ゲート割れ)
  3. **D7 両者継続が 50% 未満**(KPI.md §4 の目標割れ)
  4. **1 日の請求が 1,000 円を超えた**(設定ミス。すぐ止めて原因を書く)
  5. 課金開始(11/12)以降に**返金・誤課金の問い合わせが 1 件でも出た**
  6. ストア文言の mkt-review 承認が無い、または取り消された
- 2・3 のしきい値は §8 と同じ 40%・50% を使う(**基準を 2 つ持たない**)。広告だけ別の基準にすると、どちらの判断で止めたのか分からなくなる
- 計測の限界(ここを曖昧にしない): 帰属の根拠は **Search Ads の管理画面の「インストール数」と「消費額」だけ**。オーガニック DL と混ざる数字は **null** と書く。CPI の分母は「そのキャンペーン経由のインストール数」で、**全体の DL ではない**
- 使わなかった場合も同じ表を残す(次に判断する人が、条件だけを見られるようにする)

## 8. 未達のときの動き

判定日を過ぎて未達なら、次の 1 手を打つ。**同じ週に 2 つ以上を変えない**(どれが効いたか分からなくなる)。変える順番は「アプリの外(キーワード)→ アプリの中(導線)→ 広告」で、**安くて戻せる順**にする。変えたら、その週の数字は「比べにくい」と記録する(§7)。

| 状況 | 判定日 | 動き(1 つだけ) |
|---|---|---|
| DL が計画の 70% 未満(W1 末で 90 → **63 未満**) | 11/8 | 11/9 の v1.1 提出で**キーワードを差し替える**(§4.2 の条件)。広告はまだ開かない |
| DL が計画の 50% 未満(W1 末で **45 未満**) | 11/8 | 11/9 にキーワードを差し替え → **1 週間その効果を見て**、11/14 から §5.1 の広告枠を開く(上限内)。キーワードは v1.1 の提出でしか変えられない 1 回きりの機会なので、広告は 1 週ずらして切り分ける |
| 招待→ペア成立率が 40% 未満(**2 週続く**) | 11/13 | 獲得を止め、**招待が通る導線の改善を eng に依頼**(広告は停止)。TASKPLAN §5 の「未達のときの動き」に従う |
| D7 が 50% 未満 | 11/13 | 課金(v1.1)の前にコアループ改善(つつきの転換・通知文言)へ集中。投稿は止めない |
| 先行ペアが 5 組未満 | 10/30 | 公開日の告知で「最初の 5 組」を明示。募集文を**1 回だけ**直す |
| X の投稿が 3 日続けて出せない | 随時 | #79 を止め、承認済みの文面だけを予約投稿に回す。**認証情報は触らない**(オーナーへ) |
| 広告の請求が想定を超えた | 随時 | 即停止(§5.1 の 4)。原因を書いて mkt-review に報告 |

- 「未達」を実績より良く見せない。**計画値と実績を並べて書き、差分を消さない**

## 11. 承認と実行の流れ

1. 文面を作る(#75 / #77 / #76)
2. **mkt-lead が承認**する(下のチェックリスト)
3. **mkt-review がレビュー**する(景表法・誇大表現・体験していない機能)
4. 承認済みのものだけ **#79 が投稿**する。承認の無い文面は投稿しない。想定外の画面・認証要求・課金表示が出たら止めて人へ渡す
5. 記録: 投稿 URL と 24 時間の反応(#79 の log)

承認チェックリスト(mkt-lead / mkt-review が同じものを使う):

- [ ] 訴求の根拠(顧客の声・数値・利用実態)が書かれている
- [ ] 媒体の条件(文字数・画像・審査)を確認した。表示名 30 / サブタイトル 30 / キーワード 100 / プロモーションテキスト 170 / 説明文 4000(X は 140 字目安)

- [ ] 効果測定の分母と期間を明記した
- [ ] §10 の 8 項目に当てはまっていない

- **本書自体も mkt-review の承認対象**。承認されたら §3 のカレンダーに沿って文面の作成に入る。承認前に投稿を始めない
- **本書を変えるときも同じ手順**(改訂は mkt-lead → mkt-review)。週次の実績を表に反映する作業は #78 が行い、承認は要らない(数値を書き写すだけ)。**数値・しきい値・日程を変える**ときは承認を取り直す
