## 1. 値を表示する

リポジトリのルートで:

```bash
cd products/lien/marketing
python3 tools/verify_metadata.py --print
```

緑(OK)のときだけ、各欄の見出し・文字数・貼り付け用の本文が続けて表示される。
赤(NG)のときは 1 行も貼らない(文字数超過・罰なし原則違反・キーワードの重複・
Pairy 語の混入のいずれか。CI も同じ検査を毎 push で走らせている)。

## 3. 貼り付けの手順

0. 人間が G0 の完了証跡と ASC のチーム・アプリ(Lien)・日本語ローカライズ・対象バージョンを確認する。
   確認できなければ入力せず、#32 に不足を記録する。文言は #32 で承認済みで、
   G4 全体の close やスクリーンショット完成をキーワード・説明文保存の追加受入条件にしない。
1. 表示名 → サブタイトル → キーワード の順に、`--print` の出力をそのまま貼る
2. キーワード欄は、貼ったあとに**末尾の改行・空白が入っていないこと**を目で確認する
   (入ると 1 文字ぶん損し、検索語も 1 つ壊れる)
3. 説明文は、貼ったあとに ASC のプレビューで `◆` の見出しと空行が崩れていないか確認する
4. プロモーションテキストと新機能を貼る
5. 保存 → 「App 情報」と「バージョン情報」の両方を再読み込みし、値が残ることを確認する。
   ここでは保存まで。「審査へ提出」「公開」は別タスク・別承認なので実行しない

## 4. 入力後の検証(証拠を issue #32 に残す)

- [ ] `python3 tools/verify_metadata.py --print` の出力と、ASC の各欄が一致する(目視)
- [ ] キーワード欄にスペース・改行が無い
- [ ] 再読み込み後もキーワード・説明文が正本と一致する(これが #32 の受入確認)
- [ ] スクリーンショット(各欄 + 保存・再読み込み後。アカウント等の私的情報は除く)を issue #32 に添付
- [ ] 実施日時・実施者を issue #32 のコメントに書く

実機ストア画面の冒頭表示は、公開・プレビューが可能になった段階で別途確認する。
未公開で見られないことを ASC 保存失敗とは扱わず、未確認として記録する。
human-gate の issue #32 はエージェントが close しない。

## 5. 文言を変えたくなったら

1. `store_metadata/ja/*.txt` を直す(ASC を先に触らない)
2. `python3 tools/verify_metadata.py` と `python3 -m unittest discover -s tools -p "test_*.py"` を緑にする
3. CI(`store-metadata` ジョブ)を緑にする
4. このシートの手順で ASC に再投入する

プロモーションテキストだけは審査不要なので、季節の訴求(年末年始など)の
差し替えはこの経路で行う。差し替えの条件は `alternatives.md` §5・§8 に記録している。
