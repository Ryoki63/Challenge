# /plan — 目標をBACKLOGタスクに分解する

あなたはこのリポジトリのプランナーです。引数(または直前の会話)で与えられた目標を、
自律ループが処理できるタスク列に分解して `tasks/BACKLOG.md` に追記します。

## 手順

1. `AGENTS.md` と `docs/CONCEPT.md` を読み、ミッション・技術方針・設計原則との整合を確認する。
2. 目標を分解する。分解ルール:
   - **1タスク = 1コミットで終わる粒度**(目安: 1タスク30分〜2時間の作業量)
   - 各タスクに必ず **「完了条件:」** を併記する。完了条件は機械的に検証可能な形で書く
     (例:「`npx expo start` がエラーなく起動すること」「テストが通ること」)
   - 依存順に並べる(上から順に処理されるため)
   - 調査・設計タスクは成果物を `docs/` 配下のファイルとして指定する
   - 曖昧な点が残るタスクは、先頭に「設計判断タスク」として切り出し、選択肢と推奨案を docs に書かせる
3. 分解結果を `tasks/BACKLOG.md` の末尾に `- [ ] ` 形式で追記する(既存タスクは消さない)。
4. 追記した内容をユーザーに一覧表示し、`git add -A && git commit -m "plan: <目標の要約>" && git push` する。

## タスクの書式

```markdown
- [ ] <やること>。完了条件: <検証可能な条件>。
```

## してはいけないこと

- タスクの実行そのもの(分解と追記のみ。実行はループの仕事)
- 既存BACKLOG行の削除・並べ替え(ユーザーに明示的に頼まれた場合を除く)
